# Features

The product is **products, categories and orders** plus the admin settings that control the website, with guest checkout, delivery, payments, discounts, a wholesale form, e-mail and push notifications and a dashboard on top. Customers have no accounts.

✅ built and tested · ⏳ possible later (not built) · ❌ removed

## Built

| Area | Feature |
|---|---|
| Catalogue | ✅ two-level categories with icon + image, "top" categories for the home screen · ✅ products with options, per-option price / MRP / stock / SKU, uploaded pictures (several at once, for the product and for each option; reorder, make primary, delete; thumbnails), bulk prices, tags, content tabs, related products, SEO fields, status workflow (draft / active / inactive / archived) · ✅ stock per option with movement log and low-stock alerts · ✅ search (FULLTEXT + SKU) and filters · ✅ **sold out** switch (the product stays visible, cannot be ordered) and **featured** switch (`GET /store/products?featured=1`) · ✅ **product video**: up to 2 uploaded mp4 / webm files (each with an optional poster picture) and / or an https YouTube, Vimeo or direct link, public `videos` array · ✅ compact admin list (image, name, category, price, stock, status, sold-out and featured switches; filters category, status, stock, search) and a compact form of collapsible sections (open on create, remembered per section on edit), options as an editable table with a bulk-price popover, sticky save bar; the sub-category field disappears when the store has no sub-category |
| Guest checkout | ✅ no customer accounts: the storefront keeps the cart, `POST /checkout/quote` prices it, `POST /orders` places it (name + phone + optional e-mail + address + items) · ✅ idempotent, race-safe stock deduction, `price_changed` check · ✅ order lookup with order number + phone (also shows payment, rejection reason and "delivery fee to be confirmed") · ✅ per-IP / per-phone / per-order rate limits, item and quantity limits, honeypot field · ✅ store open / closed (a closed store still quotes, `POST /orders` answers `store_closed`) |
| Payments | ✅ cash on delivery (with a limit) · ✅ **bank transfer**: accounts in Settings, the customer uploads a screenshot (private disk, no public URL, wrong phone = 404), the admin verifies it or rejects it with a reason, the order cannot be confirmed before · ✅ card is only a "coming soon" label, never selectable |
| Delivery | ✅ methods: flat, free, free above an amount, **delivery zones** (city / area / postcode with `*` prefix, fee, free-above, minimum order, ETA, ordered, zone manager inside Settings → Delivery), fee confirmed by the owner after the order · ✅ policy for an address outside every zone (block, owner confirms, flat fee) |
| Discounts and coupons | ✅ automatic **discounts** (percent / fixed; whole store, products, categories, sub-categories; dates; priority; best one per line, never stacked) · ✅ **coupons** (code; same values and scopes; minimum order, maximum discount, total and per-customer limits, first order only, free delivery; the better of discount and coupon per line; usage counted race-safe, given back when the order is cancelled or rejected) · ✅ `POST /store/coupons/validate` · ✅ discounted prices and a label on product cards and the product page (percent discounts) |
| Persistent cart | ✅ server cart bound to a random token (`X-Cart-Token`), add / change / remove / clear, contact and coupon on the cart, prices and stock checked on every read (an unavailable line stays with a warning), expires 30 days after the last activity, `shop:prune-carts` daily, `cart_token` accepted by the quote and the order |
| Customers | ✅ a contact record created or updated by every order (found by normalised phone; orders count, total spent, first / last order) · ✅ admin Customers list with search (name, phone, e-mail) and CSV export · ✅ **abandoned carts** tab (carts with a saved phone or e-mail, items, 2 hours without activity and no order since; WhatsApp button; CSV) · ❌ registration, login, passwords, address book |
| Wholesale | ✅ public `POST /store/wholesale-requests` (honeypot, 5 an hour per IP and per phone; the customer record is found or created by phone) · ✅ admin Wholesale screen: status tabs (new, contacted, quoted, closed) with counts, search, detail with an internal note, WhatsApp button, CSV export |
| Orders | ✅ status workflow (pending → confirmed → packed → shipped → delivered, cancel before shipping, **reject** a pending order with a reason), status tabs with counts and filters (status, payment method, payment status, search), timeline, courier + tracking number, internal notes, search and filters, printable invoice / packing slip in the admin panel · ✅ **orders CSV export** (same filters as the list, formula-safe, audited, permission `orders.export`) · ✅ WhatsApp button on the order |
| Notifications | ✅ **order e-mails** (order received, confirmed, shipped with courier and tracking number, delivered, cancelled or rejected with the reason, payment proof rejected, delivery fee confirmed) and **alerts to the owner address** (new order, payment proof, wholesale request); queued after the order is saved, plain Blade templates, no images or tracking pixels, one switch per event, a test e-mail button, failed jobs shown as a count · ✅ admin **browser push** (Web Push with VAPID keys, a bell button in the header, service worker `public/admin-sw.js`): new order, payment proof, wholesale request, sent only to subscribed admins who hold `orders.view` or `wholesale.view` · ✅ sidebar badges for pending orders (plus payment proofs to check) and new wholesale requests, refreshed every 30 seconds · a mail or push failure never fails an order |
| Dashboard | ✅ date ranges (today, 7 days, 30 days, this month, all time) in shop time · ✅ KPI cards (revenue, pending amount, orders, average order, pending, cancelled + rejected, awaiting payment proof, new wholesale requests, new customers, low stock) · ✅ revenue and orders chart (plain SVG) · ✅ top 5 sellers, 8 newest orders, low-stock options, product counts, recent activity · every section only with its permission: the developer sees the catalogue widgets only |
| Store configuration | ✅ tabbed Settings page: General, Branding, Banners, Footer & Social, Currency & Tax, Orders & Delivery, Delivery, Payments, Store, Notifications, Theme (developer only), SEO – **theme** (colours, fonts from a fixed list, corner radius, shadow; public in `GET /store/settings`), store open / closed + closed message + checkout notice + delivery estimate text, agency credit in the footer, store profile, logo + favicon uploads, unlimited ordered social / footer links, footer / copyright / support hours / WhatsApp, default meta title + description + share image, currency, tax (rate, inclusive / exclusive, label), order number prefix, delivery fee / free-delivery limit / days, minimum order, COD limit |
| Banners | ✅ managed inside Settings → Banners: placements (home hero, home secondary, promo strip), title, subtitle, button text, link, desktop + optional mobile picture, start / end dates, active switch, drag-to-reorder · public `GET /store/banners` returns only the live ones in order |
| Admin panel | ✅ sidebar: Dashboard, Orders, Products, Categories, Customers, Wholesale, Discounts, Coupons, Settings, and (developer only) Access Control · ✅ every date is typed, shown and compared in the **store time zone** (`APP_TIMEZONE`, sent in `GET /admin/auth/me`) |
| Access control | ✅ exactly two accounts (developer, admin) · ✅ permissions per section and per Settings tab, switched by the developer · ✅ the developer never sees orders (API, screens, dashboard, e-mails, push, exports) · ✅ enforced on every admin route and in the panel ([ACCESS_CONTROL.md](ACCESS_CONTROL.md)) |
| Platform | ✅ audit log (including permission changes and every export) · ✅ rate limiting · ✅ expiring admin API tokens · ✅ generated OpenAPI docs (`/docs/api`, [openapi.json](openapi.json)) |

## Possible later (not built)

Online card payments (the stock model has `reserved_qty` for holds, `payments` is gateway-ready) · SMS notifications · shipping providers · a captcha on the public forms (a honeypot field and rate limits protect them now) · customer accounts, if a client ever needs them.

## Removed

Loyalty points · customer feedback and ratings · saved-item lists · customer notifications centre · FAQs and CMS pages · invoices (the printable invoice / packing slip of an order stays) · refunds · webhooks · shipment items and events · pincodes · the old account-based cart and the customer address book (coupons and a token-based cart came back in Phase A with a different design) · customer registration, login and tokens · the generic Users & Roles screen (replaced by two fixed accounts) · the Features settings tab and every feature switch.
Earlier cuts: seller onboarding · sales channels · third category level · manufacturer labels · memberships · returns · OTP · referrals · events · shipping rules · search terms · enquiries · market-specific tax and profile fields.
